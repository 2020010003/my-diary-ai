# 💌 오늘의 편지 (my-diary-ai)

> **오늘 하루의 고민과 일상을 적어주세요.  
> AI가 마음을 담은 따뜻한 응원의 편지를 보내드립니다.**

오늘의 편지는 사용자가 하루 동안 있었던 일이나 자신의 고민과 감정을 자유롭게 작성하면, AI가 그 내용을 읽고 공감과 응원의 메시지를 담은 **한 통의 편지**로 답해주는 힐링 웹 서비스입니다.

단순히 AI에게 질문하고 답변을 받는 형태가 아니라,  
**'오늘 하루를 돌아보고, 나에게 따뜻한 말을 건네는 경험'**을 만드는 것을 목표로 기획했습니다.

---

## 📌 1. 프로젝트 소개

### 서비스 이름

**오늘의 편지 (my-diary-ai)**

### 기획 배경

하루를 보내다 보면 힘들었던 일이나 고민이 생기기도 하고, 반대로 아무에게도 말하지 않았던 작은 기쁨이 생기기도 합니다.

하지만 이런 이야기를 항상 다른 사람에게 털어놓기는 어렵습니다.

그래서 사용자가 부담 없이 자신의 하루를 기록하고, 그 기록을 바탕으로 AI가 따뜻한 답장을 보내주는 서비스를 기획했습니다.

일기를 작성하는 행위에서 끝나는 것이 아니라,

> **내가 오늘 어떤 하루를 보냈는지 기록하고 → AI가 내 이야기를 읽고 → 나에게 편지로 답장을 보내주는 것**

이 서비스의 핵심 경험입니다.

---

## 🎯 2. 서비스 목적

오늘의 편지는 다음과 같은 경험을 제공하는 것을 목표로 합니다.

- 하루를 돌아보며 자신의 감정을 기록할 수 있습니다.
- 누군가에게 이야기하듯 편하게 자신의 이야기를 작성할 수 있습니다.
- AI가 작성한 내용을 바탕으로 공감과 응원의 메시지를 받을 수 있습니다.
- 단순한 AI 답변이 아니라 '편지를 받는 경험'을 제공합니다.

AI의 답변이 사용자의 고민을 해결해주는 정답이라기보다는,  
**하루를 마무리하면서 잠시 자신을 돌아보고 위로받을 수 있는 작은 공간**을 만드는 데 초점을 두었습니다.

## 👤 3. 타깃 사용자

다음과 같은 사람들을 주요 사용자로 생각했습니다.

- 지친 하루 끝에 따뜻한 위로와 공감이 필요한 사람
- 자신의 고민이나 일상을 누군가에게 편하게 털어놓고 싶은 사람
- 혼자 일기를 작성하는 것에서 한 단계 더 나아가 특별한 피드백을 받고 싶은 사람
- AI를 활용해 자신의 일상을 기록해보고 싶은 사람

# 🏗️ 4. 핵심 서비스 흐름

전체적인 서비스 흐름은 다음과 같습니다.

```text
[홈 화면]
     ↓
[일기 쓰기]
     ↓
사용자가 오늘의 이야기 작성
     ↓
[JavaScript]
     ↓
POST /api/diary
     ↓
[Python 백엔드 API]
     ↓
CODYSSEY_API_KEY를 사용하여 AI API 요청
     ↓
[Codyssey AI]
     ↓
gpt-5-mini가 따뜻한 답장 생성
     ↓
[AI 답장 화면]
     ↓
사용자에게 편지 형태로 출력
````

사용자는 복잡한 AI 설정이나 별도의 입력 방식을 알 필요가 없습니다.

그저 자신의 하루를 작성하고 **「AI에게 답장 받기」** 버튼을 누르면 됩니다.

# 🖥️ 5. 화면 구성

## ① 홈 화면

서비스를 처음 방문했을 때 오늘의 편지가 어떤 서비스인지 자연스럽게 이해할 수 있도록 구성했습니다.

홈 화면에는 서비스의 핵심 메시지를 보여주고,
사용자가 바로 일기를 작성할 수 있도록 **「오늘의 일기 쓰기」** 버튼을 배치했습니다.

또한 편지와 봉투를 연상시키는 디자인을 사용해 서비스의 전체적인 분위기를 처음부터 전달하도록 했습니다.

---

## ② 일기 쓰기

사용자가 자신의 하루를 작성하는 핵심 화면입니다.

```text
오늘 하루는 어땠나요?

[ 오늘의 이야기
  오늘 있었던 일을 편하게 적어주세요. ]

          0 / 3000

[ AI에게 답장 받기 ]
```

사용자는 오늘 있었던 일, 고민, 감정 등을 자유롭게 작성할 수 있습니다.

작성한 글의 글자 수도 화면에서 확인할 수 있도록 했습니다.

또한 아무 내용도 입력하지 않았거나 너무 짧은 내용을 입력했을 경우에는 바로 안내 메시지를 보여주도록 구현했습니다.

예를 들어:

```text
오늘의 이야기를 한 줄이라도 작성해주세요.
```

또는

```text
조금만 더 자세하게 이야기를 적어주세요.
```

와 같은 메시지를 보여줍니다.

이를 통해 사용자가 버튼을 눌렀을 때 아무 반응이 없는 것처럼 느끼지 않도록 했습니다.

---

## ③ AI 답장

AI가 사용자의 일기를 읽고 작성한 답장을 보여주는 화면입니다.

답변을 일반적인 채팅 형태가 아니라 **한 통의 편지처럼 보이도록 디자인**했습니다.

예를 들어 화면에는 다음과 같은 구조가 표시됩니다.

```text
♡

Dear. 오늘의 당신에게

[AI가 작성한 답장]

오늘도 당신의 하루를 응원할게요.

From.
오늘의 편지
```

이를 통해 AI 기능 자체보다 **'편지를 받는다'는 서비스 경험**을 강조했습니다.

---

## ④ 서비스 소개

서비스가 어떻게 작동하는지 사용자가 쉽게 이해할 수 있도록 별도의 소개 영역을 구성했습니다.

특히 다음과 같은 3단계로 서비스의 핵심 과정을 설명합니다.

```text
01. 일기를 작성해요
        ↓
02. AI가 이야기를 읽어요
        ↓
03. 따뜻한 답장을 받아요
```

또한 화면 하단에서는 실제 기술적인 데이터 흐름도 간단하게 보여줍니다.

```text
사용자
  ↓
JavaScript
  ↓
Python API
  ↓
Codyssey AI
```

# 🤖 6. AI 기능

이 프로젝트에서 가장 중요한 기능은 **일기 내용을 바탕으로 AI가 편지를 작성하는 기능**입니다.

### 입력

사용자가 일기 작성 화면에서 자신의 하루를 작성합니다.

예:

```text
오늘은 학교에서 발표를 했다.
많이 긴장했지만 생각보다 잘 끝나서 다행이었다.
그런데 친구와 조금 다투어서 마음이 좋지 않았다.
```

### 처리

작성된 내용은 JavaScript에서 `fetch()`를 통해 Python API로 전달됩니다.

```text
사용자 일기
    ↓
JavaScript
    ↓
POST /api/diary
    ↓
Python API
    ↓
Codyssey AI
```

### 출력

AI는 일기의 내용을 이해하고 공감과 응원의 내용을 담은 편지를 생성합니다.

생성된 결과는 다시 frontend로 전달되고,
JavaScript가 AI 답장 화면에 표시합니다.

# 🔄 7. Frontend → Backend → AI 구조

이 프로젝트에서는 API 키를 브라우저에 직접 넣지 않도록 Frontend와 AI API 사이에 Python 백엔드를 두었습니다.

전체 구조는 다음과 같습니다.

```text
┌───────────────┐
│    사용자      │
│   일기 작성    │
└───────┬───────┘
        │
        ↓
┌───────────────┐
│ JavaScript    │
│   fetch()     │
└───────┬───────┘
        │
        │ POST /api/diary
        ↓
┌───────────────┐
│ Python API    │
│ api/diary.py  │
└───────┬───────┘
        │
        │ API Key
        ↓
┌───────────────┐
│ Codyssey AI   │
│  gpt-5-mini   │
└───────┬───────┘
        │
        │ AI 답장
        ↓
┌───────────────┐
│ JavaScript    │
│ AI 결과 표시   │
└───────────────┘
```

이 구조를 선택한 이유는 **API 키를 사용자에게 노출하지 않기 위해서입니다.**

Frontend 코드에 API 키를 직접 작성하면 GitHub에 코드가 공개될 경우 키가 노출될 수 있기 때문에, AI API를 호출하는 역할은 Python 백엔드에서 담당하도록 구성했습니다.

---

# 🔐 8. API 키 보안

Codyssey API를 사용하기 위해 필요한 API 키는 코드에 직접 작성하지 않았습니다.

프로젝트에서는 환경변수를 사용합니다.

```text
CODYSSEY_API_KEY=본인의_API_키
```

실제 키는 `.env` 파일에 저장하고, `.gitignore`를 통해 GitHub에 올라가지 않도록 했습니다.

```text
.env
.venv/
venv/
__pycache__/
*.pyc
.vscode/
.DS_Store
```

따라서 GitHub에 공개되는 프로젝트 코드에는 실제 API 키가 포함되지 않습니다.

# 🧩 9. 주요 코드 구성

전체 코드를 하나하나 설명하기보다는, 서비스가 작동하는 데 중요한 부분을 중심으로 구성했습니다.

```text
my-diary-ai/
│
├── index.html
│
├── css/
│   └── style.css
│
├── js/
│   └── app.js
│
├── api/
│   └── diary.py
│
├── local_server.py
│
├── requirements.txt
│
└── .gitignore
```

### `index.html`

웹 서비스의 전체 화면 구조를 담당합니다.

홈, 일기 작성, AI 답장, 서비스 소개 영역과 버튼, 입력창 등의 UI가 포함되어 있습니다.

### `css/style.css`

서비스의 시각적인 디자인을 담당합니다.

따뜻한 분위기를 만들기 위해 베이지 계열의 디자인과 편지 및 봉투를 연상시키는 UI를 구성했습니다.

또한 화면 크기에 따라 레이아웃이 변경되도록 반응형 스타일도 적용했습니다.

### `js/app.js`

사용자의 행동과 AI 기능을 연결하는 역할을 합니다.

대표적인 기능은 다음과 같습니다.

```text
페이지 이동
   ↓
일기 입력
   ↓
글자 수 확인
   ↓
입력값 검증
   ↓
fetch('/api/diary')
   ↓
AI 답장 수신
   ↓
답장 화면 표시
```

특히 API 요청이 진행되는 동안 버튼 상태와 로딩 표시를 변경하고, API 오류나 timeout이 발생했을 때 사용자에게 안내 메시지를 보여주도록 구현했습니다.

### `api/diary.py`

Python 백엔드 API입니다.

Frontend에서 전달받은 일기를 확인한 후 Codyssey AI API에 요청을 보내고, AI가 생성한 답장을 다시 frontend에 전달합니다.

대표적인 처리 과정은 다음과 같습니다.

```text
POST 요청 수신
      ↓
일기 내용 확인
      ↓
환경변수에서 API Key 확인
      ↓
Codyssey AI 요청
      ↓
AI 응답 확인
      ↓
JSON 형태로 답장 반환
```

### `local_server.py`

Vercel에 배포하기 전에 로컬 컴퓨터에서 API 동작을 테스트하기 위해 만든 서버입니다.

개발 과정에서 단순한 정적 웹 서버만 사용했을 때 `POST /api/diary` 요청을 처리할 수 없는 문제가 있었기 때문에, frontend와 Python API를 함께 테스트하기 위한 용도로 구성했습니다.

# ⚠️ 10. 오류 처리

AI 기능은 외부 API와 통신하기 때문에 정상적인 상황뿐만 아니라 오류가 발생하는 상황도 고려했습니다.

대표적으로 다음과 같은 상황을 처리합니다.

### 빈 일기

```text
오늘의 이야기를 한 줄이라도 작성해주세요.
```

### 너무 짧은 일기

```text
조금만 더 자세하게 이야기를 적어주세요.
```

### AI 서버 연결 오류

```text
AI 서버에 연결하지 못했습니다.
```

### AI 응답 시간 초과

```text
AI의 답장이 늦어지고 있습니다.
잠시 후 다시 시도해주세요.
```

### 잘못된 AI 응답

```text
AI 응답 형식이 올바르지 않습니다.
```

이처럼 오류가 발생하더라도 사용자가 단순히 버튼을 눌렀는데 아무 변화가 없는 것처럼 느끼지 않도록 안내 메시지를 제공하도록 했습니다.

# 🌐 14. GitHub와 프로젝트 관리

이 프로젝트는 Git을 사용하여 개발 과정을 관리했습니다.

작업한 내용을 Git commit으로 기록하고 GitHub repository에 push하는 방식으로 프로젝트를 관리했습니다.

대표적인 작업 흐름은 다음과 같습니다.

```text
코드 작성
   ↓
로컬 테스트
   ↓
문제 발견
   ↓
코드 수정
   ↓
Git commit
   ↓
GitHub push
```

이를 통해 컴퓨터를 변경하더라도 GitHub에 저장된 프로젝트를 다시 clone하여 작업을 이어갈 수 있도록 했습니다.

# 💡 15. 개발 과정에서의 주요 고민

프로젝트를 처음 설계할 때 단순히 AI API를 연결하는 것보다 **사용자가 어떤 경험을 하게 될지**를 먼저 생각했습니다.

AI에게 일기를 보내고 답변을 받는 것만 구현하면 기술적으로는 동작하지만, 일반적인 AI 채팅 서비스와 크게 다르지 않다고 생각했습니다.

그래서 AI의 결과를 단순한 텍스트가 아니라 **'나에게 도착한 편지'**처럼 보여주는 방향으로 디자인했습니다.

또한 API 키를 frontend 코드에 직접 넣는 방식은 보안상 적절하지 않기 때문에 Python API를 중간에 두었습니다.

개발 과정에서는 단순한 정적 웹 서버로 먼저 화면을 확인한 뒤 AI 기능을 연결했고, `POST /api/diary` 요청을 처리하기 위해 별도의 Python 로컬 서버를 구성하는 과정도 진행했습니다.

이 과정을 통해 단순히 화면을 만드는 것에서 끝나는 것이 아니라,

```text
기획
 ↓
화면 설계
 ↓
Frontend 구현
 ↓
Backend 구현
 ↓
AI API 연결
 ↓
오류 처리
 ↓
로컬 테스트
 ↓
GitHub 관리
```

까지 하나의 서비스가 만들어지는 전체 흐름을 경험하는 것을 목표로 했습니다.

# 🎨 16. 디자인 방향

서비스의 핵심 키워드를 다음과 같이 설정했습니다.

> **따뜻함 · 편안함 · 위로 · 편지**

그래서 일반적인 AI 서비스처럼 차갑고 기술적인 느낌을 강조하기보다는, 편지와 종이를 연상시키는 UI를 사용했습니다.

홈 화면의 봉투 디자인과 AI 답장 화면의 편지 형태를 연결하여 사용자가 서비스 전체에서 동일한 분위기를 느낄 수 있도록 구성했습니다.

---

# 🔮 17. 향후 발전 방향

현재 버전에서는 AI가 생성한 편지를 사용자에게 보여주는 것을 핵심 기능으로 구현하고 있습니다.

향후에는 다음과 같은 기능으로 확장할 수 있습니다.

* 작성한 일기와 AI 편지 저장
* 날짜별 일기 조회
* 이전에 받은 편지 다시 보기
* 감정 변화 기록
* 월별 감정 통계
* AI 답장의 분위기 선택
* 편지 디자인 및 테마 선택
* 로그인 및 개인 일기 관리

현재는 핵심 기능인 **'일기 작성 → AI 편지 생성'**에 집중하여 서비스를 완성하는 것을 우선 목표로 하고 있습니다.

# ❤️ 마무리

**오늘의 편지**는 단순히 AI API를 연결한 프로젝트가 아니라,

> **사용자가 자신의 하루를 기록하고,
> 그 이야기를 AI가 읽고,
> 다시 따뜻한 편지로 돌려주는 서비스**

를 만드는 것을 목표로 했습니다.

작은 일기 한 편이 하루를 마무리하는 따뜻한 시간이 될 수 있도록,
기술적인 기능과 감성적인 사용자 경험을 함께 고려하여 개발했습니다.
